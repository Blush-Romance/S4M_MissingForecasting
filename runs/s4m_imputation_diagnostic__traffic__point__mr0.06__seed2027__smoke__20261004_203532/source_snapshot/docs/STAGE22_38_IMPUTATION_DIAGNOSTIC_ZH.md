# 步骤22.38：局部查询填补敏感性诊断

授权日期2026-10-04。使用22.36的Traffic S4M seed2027冻结checkpoint，
同一1648 validation窗口、batch16、历史192/未来96、CRN-v1逐batch随机状态。
第一轮只做一个seed机制定位；结果不用于宣称新模型精度提升。

## 假设及信息边界

填补值可能影响局部查询，进而影响原型检索及查询直达。仅修改原seq_x缺失位
会被原forward再次填补覆盖，因此干预发生于极值填补后mem_net的输入。
固定mask及真实观测，不使用seq_true_x隐藏历史真值。完整未来真值仅用于评分。
标准化零、历史前缀观测均值、前向填充三种替代；领先/整变量无观测用零。
前缀均值/前向填充不使用后续位置；不回填，不新增随机噪声或额外缺失。

## 路径分解

原融合 c=[r,u,z]W+b+u，r为检索向量，u为归一化查询，z为填补历史。
三替代×四路径：完整替换(rj,uj,zj)、query-only(rj,uj,z0)、
direct-only(r0,u0,zj)、retrieval-only(rj,u0,z0)。后两类与query-only可复用
完整替换时中间向量，在原_fuse_context及原S4主干上继续；不训练新网络。
query-only包含查询残差，不等同纯检索；retrieval-only提供进一步路径隔离。
独立脚本临时hook/包装实例方法，finally恢复，主模型源码不改。

## 门禁与输出

- 原始重复与输入缺失位改值负控制逐点相同；上下文重新组合与原forward逐点相同。
- 原始预测与已有CRN缓存逐窗口误差指标差<=原1e-5；mask、索引、counts精确一致。
- model.eval + mem_net.is_training=0；完整memory及模型状态前后哈希一致。
- S4初始化可能设置内核长度：首个原始空操作前后记录，只有C/l_kernel初始化
  可被记录允许；正式遍历以其后状态为冻结基准，后续不可变。
- CPU控制：全观测、领先/整列缺失、隐藏值不影响替代、前缀因果性、路径隔离。
- GPU smoke仅3batch（48窗口），无训练/优化器；正式完整103batch（1648窗口）。
- 逐窗口保存SSE/SAE、查询/检索向量漂移、预测差异、分预测步误差、最长及末端缺失。
- 预定义缺失长度分组0/1–5/6–20/>20，保存样本数；重叠窗口不作独立t检验。
- 不将原型内积分数称余弦；不以成员重合替代向量变化。首轮不缓存注意力矩阵。
- 替换变差可能只是训练分布偏移；表示漂移但预测稳定可能表明下游已缓冲。
- 干预改善不保证重训模块改善；证据不足时停止该具体假设，不自动添加注意力。
