# 步骤22.34.4：获批的固定随机状态恢复协议

用户于2026-09-08明确同意本修订。历史失败/指标/队列保留，不覆盖。

## 原值 → 新值 → 原因

- eval全局随机轨迹 → 默认关闭、显式启用的CRN-v1（Common Random Numbers，共同随机数）上下文；评估时仍按topM=100抽样，不改原型总数和模型权重。
- 不可恢复的训练结束随机状态参照 → 同一checkpoint的独立原始视图遍历参照；随后多视图遍历重放同一批次随机状态，原1e-5容差用于总体MSE/MAE及逐窗口误差一致性。
- 历史PG95缓存复用 → S4M/PG95均重新计算。不能将新S4M与旧PG95混合归因。
- 训练seed不变；评估随机状态按SHA256(`stage22_34_crn_v1:{seed}:{batch_index}`)前8字节小端值模(2^63-1)派生。上下文同时保存/恢复CPU和当前CUDA设备的PyTorch随机状态，额外视图不影响其他批次。

## 固定内容与边界

Traffic validation三seed2026/2027/2028，每组正式1648窗口、103批、batch16、输入192、预测96、862变量、8层512维。固定缺失掩码、归一化数据处理、检查点来源、topM100、融合0.5/0.25/0.25和L1/L5/L20不变。不训练、不访问test、不选择新超参数；修复收益不是创新收益。

两个模型族分别运行3批评估smoke，另跑默认关闭开关的旧S4M评估smoke；三项通过后才放行六个正式评估，共9项任务。这里只改只读推理链路，不新增训练/优化步骤，不以smoke冒充训练复现。默认关闭的RNG辅助函数必须与原抽样序列一致；默认配置回归测试必须通过。

每个任务包含独立原始遍历和多视图遍历，落盘逐窗口参照SSE/SAE（平方误差和/绝对误差和）。脚本独立回算参照指标；重复性容差不因smoke放宽。报告仍列旧validation值及与新原始分支差异。四格A=S4M/B=PG95/C=S4M+CNM-SE/D=PG95+CNM-SE，延续原归因判据，不挑最好seed。

只绑定4080 UUID，最大并发3，实际按显存峰值与安全余量补位；使用已有原子锁、OOM退避和失败分类。并发计时仅用于运行成本记录，不能充当独占GPU推理速度比较。额外原始参照遍历不计入方法前向次数。
