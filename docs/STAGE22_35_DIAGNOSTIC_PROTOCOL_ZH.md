# 步骤22.35：PG95退化诊断范围

本步只诊断，不训练、不改主模型、不读取test、不挑新的checkpoint。
使用22.34 CRN-v1三seed全部六份validation缓存以及它们的原训练日志/配置/检查点。

1. 核验固定资产、指标回算、同seed两方法的训练配置差异、实际训练轮数/优化步数和最佳轮次。训练选模用观测目标MSE；最终评价用完整目标MSE/MAE，明确两者不等价。
2. 固定原始与多尺度两条路径，分别统计PG95相对S4M的逐窗口误差变化：全量、四个等长时间段、历史缺失率[0,0.2)、[0.2,0.3)、[0.3,1]。分组只是描述，重叠窗口不当独立样本，不报显著性、不拟合选择器、不按结果改分组。
3. 查看六checkpoint的原型数量、两两余弦相似度及中心化有效秩。原型数量小不能单独认定表示坍缩或导致精度损失。
4. CPU构造同seed S4M/PG95，检查公共参数是否同初始化；构造时使用原日志解析出的参数。检查是当前源码的控制流复现，历史初始权重未保存，不冒充对历史权重的直接测量。
5. 训练期门接受率/不变性损失是全训练平均，不能当作最佳epoch的统计；小loss数值不代表小梯度，缺少逐模块干预不能下因果结论。

工程完成判据：单元测试及独立合成smoke通过，正式CPU诊断/源工件哈希/自动报告全部落盘。若没有因果证据，下一步只推荐最小可识别的机制实验，不直接启动大规模改模。
